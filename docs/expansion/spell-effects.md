# Spell & Effect Studio

The **Spell & Effect Studio** is a separate application with Spells and Effects workspaces. Start `npm run dev:spells` and open `http://127.0.0.1:5177/`. It does not require the game or map editor to be open. `npm run mcp:spells` starts its independent stdio MCP server; the editor service must be running.

## Embedded authoring assistant

Open **Settings** to save an OpenAI API key and select the authoring and image models, then open **Assistant**. The key lives in the operating-system credential store (Keychain on macOS, Credential Manager on Windows, Secret Service on Linux). There is no plaintext fallback: unlock that store if it is unavailable. The key is not returned to the browser, agent, tool results, or project files. Removing it revokes subsequent provider requests. This is a local, single-user workbench, bound to loopback; it is not a remotely hosted multi-user service.

Eve starts on demand using the Node 24 runtime installed by `npm install`. It receives a short-lived local proxy capability; only the editor backend injects the real OpenAI key into requests to OpenAI. Chat and tool history stay in ignored `tooling/spell-editor/agent-app/.eve/` data. Requests, canvas images and generated-art prompts are sent to the configured OpenAI account when used. Image generation is billed by OpenAI.

The complete authoring skill is `tooling/spell-editor/agent-app/author-spells/SKILL.md`. `agent/instructions.ts` imports it directly as the system prompt: there is no external skill discovery or filesystem tool. Edit that one guide when authoring practices change. It explains deterministic mechanics, reusable visual layers, schema discovery, revision-safe publication, folders, unit bindings, image generation and preview verification.

The five tools—`studio_schema`, `studio_author`, `studio_canvas`, `studio_image`, `studio_asset_image`—share contracts in `tooling/spell-editor/shared/authoringTools.ts` and implementations in `server/authoringTools.ts`. Both Eve and MCP call those same services. `publication.status` compares a saved spell/effect with the current publication; it is a read-only equality check, not a version pin. Canvas requests target the agent's browser tab and cannot replace an unsaved draft. Images use GPT Image 2.5, retain their original source and generation metadata, and publish 512px PNGs through the canonical asset pipeline; transparent images retain alpha. Existing asset IDs cannot be overwritten. The assistant has no shell, arbitrary file access, or API-key tool.

The UI uses shadcn components and a zinc theme; the game debug/profiling overlay is disabled in this host. Server implementation changes require restarting `dev:spells`. Content publication deliberately reloads the client without restarting the backend or interrupting agent work.

## Current capability set

The current simulation compatibility marker is `declarative-sim-90`. The published catalogue contains 83 spells and 127 reusable effects (2026-10-04). The milestone history below records earlier counts, compatibility markers and artwork states; later entries supersede them. The scoped mechanics, source resources, multiplayer categories, proof artwork and embedded-assistant acceptance pass are complete. This is a verified capability baseline, not a promise that external providers can never fail. World/economy operations are explicitly excluded as described under Deferred by user.

Holy Light Lite demonstrates the first complete direct-cast lifecycle: target a visible living unit, heal an ally for 100 or damage an enemy for 50 through normal combat mitigation. It reserves 25 mana, prepares for 12 simulation ticks, releases, recovers for 8 ticks, and starts a 200-tick cooldown at release. One tick is 25 ms. Turning can precede preparation. Stopping or invalidating preparation refunds the reservation; stopping recovery does not refund released effects.

The strict schema supports rank parameters; unit, ground and self targeting; ally/enemy branches; heal/damage; channelled waves; homing projectiles; bounded chains; piercing lines; timed statuses and periodic damage; passive auras; temporary summons; dispels; and autocast. Unknown operations fail validation.

**Blizzard** targets visible ground within 18 units. It reserves 60 mana, prepares for 12 ticks, then channels six waves at 40-tick intervals. Each impact damages up to 64 living enemy units within radius 5 for 30 spell damage through normal mitigation. The first impact is one interval after release; the area remains fixed and victims are selected afresh in stable entity-ID order for every wave. Moving, stopping, stun, death or owner change ends remaining waves. Only pre-release cancellation refunds mana; cooldown starts at release. Already applied damage stays applied. The next wave, index and channel clocks are saved/checksummed. Losing sight of the area after release does not retarget or cancel it.

These are declarative `targeting.kind: point`, `targeting.radius` and `cast.channel` capabilities, not a Blizzard opcode. `onRelease` is the impact program: once for direct delivery, once per wave for channel delivery.

## Expansion milestones (historical, beginning 2026-10-02)

The first expansion batch adds independent operation recipients, signed/ranked modifiers, silence and damage-breakable sleep, finite shields and damage immunity, deterministic combat reactions, persistent zones/toggles, unit/self channels and health/mana transfers. These use the same schema in the inspector, MCP, assistant and game. AI evaluates observed operation recipients through the same selector as execution. Pending reaction records, proc counters, absorption pools and persistent clocks survive save/load.

Published mechanical proofs: Healing Wave, War Stomp, Frost Nova, Inferno (forest spirit summon), Silence, Sleep, Frost Armor, Bash, Roar, Howl of Terror, Armor Hex, Anti-Magic Shell, Absorption Shield, Flame Strike, Immolation, Lightning Shield, Life Drain, Siphon Mana, Mana Burn, Tranquility and Mana Shield. These are capability proofs, not claims of exact Warcraft balance or finished visual parity. Their initial visual layers and reused icons still need an art pass.

Operation `query` chooses its own center, radius, relationships, inclusion rules, ordering and cap; `target: point` summons execute once regardless of area victim count. Healing chains can skip full-health recipients. Persistent effects are independent of cast recovery, while channels hold the caster and cancel on interruption; unit channels also cancel on target loss, visibility loss or tether break. Negative armor increases physical damage through the shared armor formula. Damage immunity currently suppresses damage, not arbitrary negative statuses.

World operations now include Blink, Mass Teleport and Far Sight proofs. `teleport` resolves arrivals through the unit's existing spatial clearance and clears stale movement; `preserveOffset` keeps relative group formation where space permits. Group passengers are processed in declared stable query order and blocked passengers remain in place. This is a partial-placement policy, not an atomic all-or-nothing group transaction. `vision` creates a bounded, saved sensor with rank-scalable duration/radius, terrain-occlusion policy and optional caster-death cleanup. It updates shared-team observation and real fog exploration, and expires independently of cast recovery. Unseen point targeting is explicit; unit targets still require visibility. The timeline shows vision lifetime. AI bindings can declare `intent: escape | reinforce | scout`; tactical choices use observed entities and visible/explored terrain only. Ordinary combat spells retain utility scoring.

Concealment and detection now have published Wind Walk, Invisibility and True Sight proofs. Concealment has a deterministic fade boundary, configurable attack/cast reveal and optional ranked attack bonus. Enemy targeting, weapon perception and death reports honor detection; allied renderers retain a faded model. Area effects still affect concealed recipients. A detector needs ordinary sight plus terrain line of sight; remote vision only detects when its operation explicitly enables `detectInvisible`. The workbench uses an omniscient faded preview. Live rigs and instanced crowds share a screen-door fade, including their depth pass. The simulation build is now `declarative-sim-73`; earlier saves/peers are incompatible. The expansion proofs currently reuse command artwork and still need final dedicated icons and visual polish.

Temporary status forms now include Hex (our tree-frog asset, disarm/silence/item restriction and slow) and Avatar (visual growth, health/armor/damage modifiers and spell-damage immunity). `form.asset` and `form.scale` affect presentation, keeping body clearance, entity identity, ownership, inventory and orders intact. The newest form takes precedence; removing it exposes an earlier form or the authored appearance. Health is capped on expiry/dispel after aura reconstruction. Metamorphosis demonstrates `form.combatProfile`: an armed unit definition supplies the weapon policy, including range, timing, damage type and projectile/shell behavior. Base weapon damage/cooldown come from that profile; existing hero progression, equipment, research eligibility and status bonuses still compose on the original entity. The latest form owns the complete form, so a newer visual-only form uses the original weapon until removed. Unreleased attacks and charges are canceled when profiles change, preserving cooldown; released arrows/shells retain launch-time policy and damage through expiry and save/load. Flying/ground transitions and spell-operation immunity are implemented in the later milestones below. The preview swaps only changed subjects and discards stale asynchronous model loads.

Spell eligibility now supports `targeting.filter` and operation `filter` with optional `heroes`, `summoned`, `minLevel` and `maxLevel`. Aim filters also constrain default area/line/chain/aura recipients; independently queried operations use their own filters. Spell Ward demonstrates status `spellImmunity: hostile` (friendly spells still work); `all` blocks friendly spells too, including self applications. `piercesSpellImmunity` bypasses this operation gate only, not independent damage-type immunity, armor or shields. Eligibility is checked before mana escrow, again at release, and at delivery/each persistent pulse. Becoming immune cancels targeted channels/tethers; areas skip immune recipients before applying caps. Existing statuses are not purged, but their periodic damage is suppressed while protected. Dismiss Summon demonstrates a piercing dispel restricted to summoned non-heroes up to level six. Observation exposes whether a visible unit is summoned, and AI uses the same filters/protection. These proofs reuse existing effect artwork; dedicated art remains pending.

Unit definitions can declare `unitNature: organic | undead | mechanical`; units default to organic, while buildings have no unit nature. This targeting metadata does not change armor, movement, models or temporary forms. Both aim and operation filters accept `natures`. `targeting.condition` and branch conditions share a bounded evaluator: a `matches` leaf selects caster or target traits and optionally its relationship to the caster, and an `all`/`any` group combines at most eight leaves (no nested groups). Each branch evaluates its actual recipient, including independently queried areas. Holy Light heals allied organic units or damages enemy undead; Death Coil heals allied undead or sends a damaging projectile to enemy organic units. Mechanical targets and the opposite relationship/class combinations are invalid. The original Holy Light Lite stays available. Encounter controls can override caster and target nature independently without replacing their models; reset and timeline replay retain these settings. AI, targeting highlights, cast validation and delivery all share the same predicates.

Weapon modifiers now support ranked `combatModifiers` on learned passives or applied statuses. Critical Strike rolls at melee/arrow release and applies the strongest successful multiplier before armor. Evasion uses the strongest active chance at impact, before shields, lifesteal and weapon reactions; it affects direct melee/arrows only, not spells or siege splash. Cleaving Attack copies a percentage of raw successful melee damage (including critical damage) into a bounded forward arc, excluding the primary target and allies, with stable nearest/ID ordering, target filters, optional buildings, wall/layer checks and a maximum of 32 recipients. The strongest cleave percentage wins with stable declaration ties. An evaded or fully absorbed primary cannot cleave. Cleave is independently mitigated and cannot produce more cleave, item on-hit or weapon-hit procs; defensive damage reactions can still respond. Duplicate bindings/status stacks of one grant do not multiply its policy. Weapon modifiers are captured before attack-triggered concealment removal; arrows save their rolled damage and critical presentation identity, surviving source loss. `criticalStrike`, `evaded` and `cleaved` are ordinary effect-binding events and timeline markers. Critical Strike, Evasion and Cleaving Attack are published three-rank proofs; they reuse existing command icons and need final dedicated artwork. No spell-name branches or content callbacks are used.

Mana-paid weapon enhancements use `combatModifiers.attackBonus` on passive grants or statuses: ranked `amount` and `manaCost`, weapon kind (`melee`, `projectile`, `any`), optional target filter and `blockedBySilence`. At a valid weapon release, the strongest affordable matching grant pays once and adds ordinary weapon damage before critical scaling and mitigation; stable declaration order breaks ties. Cancelled windups do not pay. Insufficient mana or silence leaves a normal attack. Misses and absorbed hits do not refund release mana. Paid projectiles save the bonus and effect identity, continue after toggle-off/source removal, and reconstruct their visual delivery after loading or scrubbing. Only damaging hits emit `enhancedHit`; `weaponEnhanced` is the melee-release cue, and ranged flight uses `projectile`. Searing Arrows is the three-rank toggle proof (10/20/30 bonus, 8 mana per arrow); select Archer and enable Combat in the independent encounter controls. This proof does not yet implement a manually targeted single-shot/autocast attack command. General attack-release hooks are now supported below; death and kill triggers are documented below. Its initial command icon is reused pending the art pass.

Selective control prevention is declared through a status `controlImmunity` list: `stun`, `root`, `silence`, `disarm`, `itemBlocked`, `moveSlow` and `attackSlow`. Incoming spell-status components matching that list are recorded in a saved prevention mask; removing the ward cannot revive those prevented components. A fully prevented control-only application creates no status or status-applied visual. Mixed applications retain their damage, armor penalties and other independent payloads. Older controls are suppressed only while immunity is active: their timers and periodic damage continue, and still-live controls resume when immunity expires or is dispelled. This is suppression, not cleansing. The legacy broad `modifiers.controlImmune` grant resolves through the same policy. Movement, charges, traffic, casting/item gates, shell slows and resolved attack/movement speed honor it. AI skips wholly prevented control-only effects but can still value a damaging composite; only observed protection is used. Unstoppable is a custom three-rank neutral proof with 4/6/8-second, dispellable ally protection; it is not claimed to reproduce a particular Warcraft spell exactly. The schema is available through all-attributes authoring, MCP and the assistant. Its initial command icon is reused pending final artwork.

Ethereal is an authored status combat state (`ethereal: true`), independent of suppressible disarm. It forbids outgoing weapon attacks and non-spell weapon acquisition, and prevents non-spell damage at impact, including existing missiles and shell splash. Spell-type weapons and spellcasting remain allowed; physical shell slows cannot leak through. Units keep identity, visibility, body clearance and movement. Generic ranked `damageTakenPermille` maps known damage types to 0–5000; the strongest amplification and strongest reduction combine once before armor and shields (duplicate statuses never compound exponentially). Damage immunity is checked before consuming shields. Observed AI uses the same factors to score damage, with no hidden-state reads. Generic `form.opacity` (0.1–1) uses the live/baked screen-door visual path without granting invisibility. Banish composes ethereal, a 50% movement slow, 1660 spell-damage multiplier and half-opacity appearance. Its durations are 12/15/18 seconds, reduced to 4/5/6 on heroes, with 75/60/50 mana, based on the [classic Blood Mage reference](https://classic.battle.net/war3/human/units/bloodmage.shtml); world range is adapted to this game's scale. Our current damage vocabulary uses `spell` for magical damage; a separate magical weapon category is not implied. Its reusable looping shroud follows actual status lifetime, and its icon remains reused pending final artwork. Save/load, scrub replay, dispel/expiry, arrows in flight, shell slow prevention, control immunity and authored multipliers have simulation/workbench coverage.

Death triggers now use `event: death`, available to learned passive bindings and `whileStatus` grants. The hook captures the holder before status cleanup/removal, including rank, owner, camp allegiance, exact point and witnessed viewers. It is not an alternate resurrection path: use explicit operation queries for live recipients or `target: point` for summons/vision; bare dead-holder recipients are rejected except the explicit retained-hero `revive` operation. Death reactions execute through the ordinary interpreter after combat, in a durable FIFO, at most 128 programs per tick with 512 pending. Overflow additions are deterministically dropped; carried work survives saves and validates definitions, trigger references, rank, cast IDs and map bounds. Deaths caused by a reaction may enqueue further deaths without recursive calls. Ordinary hit reactions still cannot proc themselves. Repeated death notification for removed/fallen entities is ignored; resurrection can produce a new death later. The default operation source/ownership is the dead holder. Status grants can instead select their original applier, as described below; killer-as-executor for a victim death remains separate work. Death Burst is a custom neutral proof with ranked 80/120/160 spell damage in a six-unit enemy query and a reusable flash/spore burst at the saved point. It is not a claim of exact Warcraft spell balance. Enable it with Cast in the workbench, then use Encounter → Remove caster; rewind/reset replay that intervention deterministically. No additional AI cast logic is required for passive death hooks. Its command icon remains reused pending final artwork.

Kill triggers now use `event: kill` on learned passives or timed status grants. Ordinary melee, arrows, shells, item damage, periodic damage and spell hits share one lethal-credit callback after mitigation and rescue. In a simultaneous damage batch the first hit that exhausts remaining health gets credit; later overkill cannot steal it. Kill hooks require a living hostile killer whose owner still matches the damage source. A source already dead (including a removed projectile shooter), simultaneous mutual kills, friendly kills, cleanup and summon expiry do not earn rewards. A queued reward also cannot transfer to a newly converted owner. `filter` checks defeated-unit traits and `includeBuildings` explicitly opts into structural kills. Operations can affect `caster`, an explicit live query or `point` at the defeated victim; bare dead-target recipients are rejected. Death and kill programs share the saved, bounded `spellLifecycleReactions` queue. The kill effect captures only observers who witnessed both actors. Soul Harvest demonstrates ranked health/mana restoration and independent departure/restoration effects. It is a custom category proof, not a Warcraft balance replica; Black Arrow's impact mark is now supported below. Test it with the workbench Combat scenario enabled and a low-health enemy; ordinary Remove target intentionally does not credit a kill. Dedicated artwork remains pending.


Doom adds a generic `lifetime: untilDeath` status (amount 0, no hero-duration override or aura) and `executor: statusSource` on a death trigger with `whileStatus`. This executes as the original applier, preserving owner, camp, classification and fallback position through caster removal, conversion, projectile travel, persistent application and save/load. A still-living original-owner source uses its current position; a removed or converted source uses the saved application context. Trigger counters/chance remain on the holder; source-executed death triggers cannot charge mana. Use `target: point` for the deceased recipient location, queried live recipients, or `caster` for restoration only if the original caster is still alive and retains ownership. Refresh replaces the saved applier. Internal source snapshots are not exposed through observed statuses; death visuals show the victim point, not an unseen applier position. Doom applies nondispellable silence/item blocking and 40 spell damage per second until death, then summons one existing forest spirit for 180 seconds for the applier. Its mechanics follow the [classic Pit Lord reference](https://classic.battle.net/war3/neutral/pitlord.shtml), with game-scaled range and an explicit forest-spirit adaptation in place of a Doomguard. The icon is reused pending final art. The workbench displays Until death, bounds its inspection timeline, and supports source-removal, rewind and reset through the shared interpreter.

Weapon impact marks: an ability may declare up to eight reusable `statuses` templates. Declaring a template does not apply it. `combatModifiers.attackBonus.status` references one target-only template with no query and an independent lifetime (duration or untilDeath). A successful damaging melee/arrow hit applies it before lethal HP resolution; evasion, full absorption, overkill and removed targets apply nothing. Marks require a currently hostile recipient and follow ordinary filters/control/spell immunity; ordinary weapon damage remains independent. Bonus 0 is allowed for a mark-only policy. The chosen grant saves rank, status ID and original source context at release, so toggle-off, source death or conversion cannot steal an arrow or its later death summon. Save validation checks the policy/rank/bonus, template and source identity. Marks use the existing bounded status store and ordinary death-reaction queue, not recursive callbacks. Black Arrow is the published toggle proof: 2/10/20 damage, six mana, a two-second dispellable organic non-hero mark and an 80-second forest-spirit summon. Values and behavior are inspired by the [classic Dark Ranger](https://classic.battle.net/war3/neutral/darkranger.shtml) and [Dark Minion](https://classic.battle.net/war3/neutral/darkminion.shtml) references; this adapts the model; corpse consumption and manual single-shot targeting were added in subsequent milestones below. Reusable flight/mark/manifestation effects use violet particles; the command icon is reused pending final art. No per-spell interpreter, editor or AI branches were introduced.

Ranked summons: `summon.definition` accepts a fixed unit ID or `{byRank: [id, ...]}` with exactly one entry per ability rank. Every entry is validated against the unit catalogue before publication. `durationTicks` accepts fixed ticks or a numeric rank parameter (1–144000), while quantity remains capped at eight per operation. Release and lifecycle-trigger paths use the same resolver. Saves record source, cast, selected rank, start and expiry; restore checks the resolved creature/lifetime and rejects mismatches atomically. Replacement removes the source’s previous group even when its rank used another definition. The editor exposes a Per rank definition mode with unit selectors, and timeline durations resolve the selected rank. Black Arrow now chooses Lesser Shadow Spirit, Shadow Spirit or Greater Shadow Spirit (215/290/405 HP, 10/16/18 melee damage, 80-tick attack cycle, 80-second lifetime). These reuse the existing forest-spirit model; integer damage is an adaptation of the classic minions’ fractional average damage. They add no supply cost.

Corpse foundation: authoritative `corpses` records retain dead non-hero, non-summoned organic/undead units for 2400 ticks (60 seconds), capped at 512 with oldest-death/ID eviction. Mechanical and contained/garrisoned units do not leave usable records. Corpses occupy no cells and add no supply; inventory, equipment, orders and statuses are not retained. Unit definition, owner, position, progression and spell ranks/cooldowns are retained for future consumers. Mana, regeneration and pending casts are cleared. Saves/checksums include corpse records and reject duplicate/live IDs, invalid definitions/ranks, bounds and expiry. Heroes continue using the existing fallen-hero revival path. Resurrection now consumes these records through the shared operation described below.


Resurrection: `resurrect` runs once at a `caster` or `point` anchor with a corpse query (ranked radius, ally/enemy relations, optional traits, nearest/strongest order), ranked count (1–8), health (1–1000 permille), mana (0–1000 permille), placement search radius and explicit supply policy. Strongest sorts level, maximum health, distance, then ID; progression contributes to strength. Only currently visible, unexpired corpses participate. Successful creation consumes the record once and allocates a fresh entity ID, preserving original owner, progression, learned ranks and absolute cooldowns. It never duplicates equipment or transient actions. Blocked placements and supply failures leave corpses available. `allow-over-cap` bypasses supply capacity, never the hard unit limit or reservations. Area casts may succeed with zero eligible corpses, like other empty-area effects; AI scores only visible eligible corpse knowledge and samples corpse centers for point-targeted variants. Each raised unit emits `resurrected`; effect audiences must also see the raised position.

The published **Resurrection** proof returns up to six allies at full health and zero mana within radius 12, costs 200 mana and has a 240-second cooldown; it can exceed supply capacity. Original-owner, strongest-first and supply behavior follow the [classic Paladin reference](https://classic.battle.net/war3/human/units/paladin.shtml), with range adapted to game scale. The independent **Fallen allies** encounter preset supplies six real simulation corpses; any setup also has a fallen-target switch. Corpses hold their death pose in the preview and are replaced by live subjects on revival. Cast/reset and both scrub directions rebuild the same result. The generic golden rise effect binds per `resurrected` event; the command icon is reused pending the art pass. Live workbench verification and 13 focused tests cover owner preservation, limits, blocked/expired/hidden candidates, strongest selection, repeated death, spell-state retention, point targeting, observations and save/replay. Retained-hero reincarnation is described below; temporary reanimation and corpse-consuming summons are described below.


Corpse-consuming summons: `summon.corpses` adds the shared corpse selector plus ranked `maxTargets`. `amount` is units per consumed corpse; their product is limited to eight at every rank. It uses a single caster/point anchor, never a live-unit query. Selection considers only visible, unexpired corpses, including optional neutral relations; neutral-camp affiliation survives death and save/load. Allegiance is independent of whether the actor is alive. Each successful group consumes its corpse exactly once and emits `summoned` at that location. Zero-placement or hard-limit failures leave the corpse available; a partial group consumes one corpse. Summons belong to the spell source, not the corpse's former player, and use the existing ranked definition/lifetime, dispel and death cleanup. Ordinary and corpse summons share one placement path that enforces the unit limit including queue reservations. Replacement occurs once per operation, only after a valid new placement exists, so a failed replacement preserves the previous group.

**Raise Dead** is published under `/spells/units/necromancer`: one selected-area corpse creates two lesser shadow spirits for 40 seconds, with 75 mana and an eight-second cooldown, inspired by the [classic Necromancer reference](https://classic.battle.net/war3/undead/units/necromancer.shtml). Passives still cannot autocast. Effects remain ordinary target-anchored `summoned` bindings, whose point is the consumed corpse. Choose Fallen allies (or enable fallen targets on another independent setup), Cast, then click near a corpse. Fourteen focused tests cover consumption, limits, partial/blocked placement, ranked products, simultaneous casters, interruption, source loss, replay, neutral camps and optional autocast. The live workbench timeline and scene were checked. Its icon/model reuse remains part of the final art review.

Temporary reanimation extends `resurrect` with optional `ownership: original | caster` and ranked `durationTicks`. Omitted lifetime means permanent; original ownership remains the default. A temporary unit shares summon expiry/cleanup and cannot leave another usable corpse. It keeps its original unit definition and associated supply cost; the explicit resurrection admission policy still controls capacity checks. The saved summon provenance includes its consumed corpse ID, and validation rejects invalid clocks, ranks, incompatible definitions, duplicate lineage and references to a still-live/retained corpse. Source death does not shorten its independent lifetime. AI accounts for the resulting owner and saves temporary-army casts for nearby threats.

Reusable creation grants: `summon.grants` and `resurrect.grants` reference up to eight unique declared status templates. A grant must target the created unit only, with no query or instance lifetime. Initial grants bypass spell-immunity rejection so one protection cannot block its siblings; all later ordinary spells respect that immunity. Normal component-control policies still apply. Grants use existing status state, rank resolution, visuals, expiry, dispel and lifecycle hooks; no spell-specific runtime path is required. They apply only to successfully created units, including ordinary and corpse-consuming summons. Detached lifecycle effects preserve their public visual origin.

## Workbench

- **Layout:** Library and Inspector header buttons hide or restore either sidebar. Drag the dividers or focus them and use arrow keys to resize. Each workspace remembers its layout and last expanded widths locally. Collapsing keeps the forms and canvas mounted, preserving unsaved edits.
- **Spells:** the Ability inspector provides quick values and a **Configure all attributes** dialog. Its Mechanics & ranks tab exposes the complete supported definition schema: targeting, cast lifecycle, delivery, programs, statuses, modifiers, summons, rank values and AI policy. The Animations & effect links tab maps semantic clips and authoritative events to published effect IDs. Nested operations, arrays and optional fields are editable without JSON. Unit bindings have their own complete configuration dialog.
- **Effects:** a standalone visual stage with the same renderer, biome lighting and resource catalogue as the game. Create effects, add/reorder/duplicate/mute/solo layers, edit textures and parameters, undo/redo, preview and publish. Spells cannot edit these layers; they only reference effects.
- **Layers:** rings, glows, pillars, billboards, streaks, bursts, lights, rain, missiles, beams, wavefronts and generic particle emitters. Particle controls include burst/continuous emission, lifetime, rate, cone direction, speed variation, gravity, drag, spawn radius, start/end size, spin and opacity envelopes. Layer start offsets, source/target anchors and spatial offsets compose a reusable effect. Cyclic rotation, scale and opacity animate ground symbols. Rain retains angle, randomized launch delay and per-shard impact fragments.
- **Libraries:** compact, windowed Headless Tree browsers with a visible root, search, small spell icons, keyboard selection, multi-selection, drag-and-drop, and create/rename/move/remove-empty-folder actions. Existing spells are grouped under `/spells/heroes` and `/spells/units`; effects add a folder for each spell. `/environment` is available for reusable scenery effects. Folder changes preserve document IDs and links. Search includes descendants of matching folders. Only visible rows are mounted.
- **Encounter:** independent setup selection, stationary target dummies by default, optional combat, models, team relationships, health, distance, biome, classification overrides and active rank. Cast resets the fixture immediately, then requests a unit/point target or immediately activates self/passive spells. For persistent toggles, Toggle off sends the normal gameplay command in the existing take and records it for timeline replay. Test mana/cooldown do not restrict repeated casts. The game definitions retain their costs.
- **Transport:** spell timeline and event inspector use actual simulation ticks; seeking reconstructs the encounter. Effect playback is visual-only and has its own layered timeline, seek, restart, stop, repeat, speed, deterministic seed, source/target distance and sustain controls. Preview solo/repeat controls never modify published effects.

The backend creates an isolated instance of the actual `Game` simulation. It runs at 40 ticks per second and never edits a production map. Renderer frames cannot apply healing or damage. Preview reset clears actors and cues; the event inspector shows authoritative lifecycle outcomes and a state checksum.

Save validates and commits the draft with an expected revision. Publish requires saved changes and replaces the current definition under its stable ID; already running matches retain their loaded content. The unit-binding panel attaches a **published** ability to an existing unit. AI-only bindings have no player button. Bindings and drafts reject concurrent edits rather than overwriting them.

## Files and publication

Stable-ID source directories are independent of the logical library folders:

```text
content/abilities/ability.core.holy-light-lite/definition.json
content/abilities/ability.core.holy-light-lite/presentation.json
content/abilities/folders.json
content/effects/effect.core.holy-light-lite.released-1/effect.json
content/effects/published.json
content/effects/folders.json
```

`content/abilities/published.json` and `content/effects/published.json` hold the current published spell and effect libraries. Spell presentations contain `effects` bindings, never embedded visual layers. Each binding chooses an effect ID, lifecycle event, caster/target anchor and finite/status lifetime; optional radius/delivery bindings adapt its dimensions to the authoritative event. Publishing an effect updates every linked spell in newly loaded content. Draft changes remain private until publication. There are no historical release files, version selectors, or dependency pins. Texture resources remain in the standard Asset Studio pipeline; Holy Light uses `asset.effects.holy-light-spark` and `asset.effects.holy-light-sigil`; Blizzard also uses the original generated `asset.effects.blizzard-ice`, role `image`, index `1`. Each source and 256px runtime image is in its asset's own folder. Spells never name uploaded filenames.

Spells reference assets by stable ID and role/index. Republishing a texture under the same ID updates its consumers without republishing their spells. Publishing still verifies current resource bytes and rejects missing references; a referenced asset cannot be removed until its consumers are updated. Startup validates the current definitions and image references. Multiplayer holds early turns until peers agree on simulation build and the SHA-256 identity of published content. The same serializable source is passed to the worker, validated, frozen and checked against the main-thread registry fingerprint.

This version resolves the **local published library bundled with the game**. Downloading community packs, per-map package selection and remote registries are later work. There is no arbitrary-code spell import or active-match hot replacement.

## MCP workflow

Configure an MCP client to run `npm run mcp:spells` from the repository root. The server exposes:

- `spell_schema {}`: discover document and command schemas.
- `spell_author {command: ...}`: the same operations used by the application.

Start with `list`, `catalog` and `read`. Keep the returned revision. Modify the returned document, then call `validate`, `preview.load`, `preview.cast` and `preview.step`. Inspect recipient health/statuses, checksum and events. Each `preview.cast` resets the fixture and starts a fresh take, bypassing mana costs and cooldowns only in the cloned preview definition; published gameplay definitions retain their values. Passive abilities are absent until Cast grants the ability and activates the normal aura interpreter. Use `save` with `expectedRevision`, followed by `publish` with the newly returned revision. New documents use `expectedRevision: null` and unique definition/presentation IDs.

```json
{"command":{"op":"read","id":"ability.core.holy-light-lite"}}
```

A preview accepts the whole document plus settings; omitted setting fields receive defaults:

```json
{"command":{"op":"preview.load","document":"<document returned by read>","settings":{"relationship":"enemy","targetHealth":300,"distance":6}}}
```

The `document` placeholder above must be replaced by the JSON object, not a string. Then:

```json
{"command":{"op":"preview.cast"}}
{"command":{"op":"preview.step","ticks":30}}
```

For bindings, `binding.read` takes a unit definition ID and returns its caster policy and the content revision. `bind` takes that definition, a complete caster policy and `expectedRevision`. It validates against published abilities and the full game registry before writing. Batch authoring can sequence these commands per document without driving the browser.

`preview.autocast {enabled}` toggles the same saved autocast command as the game. `preview.attack` is an MCP-only diagnostic command; enable real attacks in encounter settings first. The visual workbench never exposes unit movement or attack orders. `settings.initialStatuses` accepts published status-spell IDs for testing dispels. The status selector is populated from published abilities that declare status operations.

`preview.seek {tick}` pauses and reconstructs a frame in the active take. `preview.target {entity}` selects a unit (0 clears selection); The UI uses `preview.beginCast` to reset immediately and enter targeting for unit/point spells (self spells and auras fire immediately). A canvas click sends `preview.confirmTarget {target}` to fire; invalid targets keep targeting open, and Escape cancels it. The target indicator follows the pointer. `preview.cast` remains the direct-fire automation command. Changing the aim ends the old take. The always-visible Setup dropdown provides single/five enemy ants, single/five allied ants, a mixed hostile neutral camp, empty ground (`targetCount: 0`), and caster-only. Choosing a preset resets and respawns the fixture. Settings are independent of spell selection and survive switching abilities; ally presets start wounded for healing tests. Neutral camp members use neutral ownership and the normal hostile-camp rules. Fixtures default to stationary targets. The opt-in Combat scenario setting enables movement and weapon attacks, rendered with the shared attack-contact timing and arrow/shell renderers; passive preview ticks retain combat definitions for melee/ranged eligibility but skip autonomous combat and movement while running the actual spell lifecycle, damage, status, summon, and cast-facing systems. The stage uses only a grid, without unit pedestals. Initial target status options come from published definitions containing status operations, rather than a built-in list of spell names. A no-target unit spell is rejected normally; point spells still fire on empty ground. New fixtures remain idle until Cast.

Other preview commands are `preview.aim` (integer world position), `preview.state`, `preview.play`, `preview.stop`, `preview.reset`, `preview.replay`, `preview.rank`, `preview.stun`, `preview.displace` and `preview.kill`. MCP and UI control the same encounter. A newly loaded MCP document is reflected by a clean UI; unsaved UI edits are retained.

### Independent effect and folder commands

Use `effects.list`, `effects.library`, `effects.read`, `effects.validate`, `effects.save` and `effects.publish` for the visual library. Save/publish use optimistic `expectedRevision` concurrency checks, not version pins. `effects.preview.load` accepts a visual effect and preview settings; `effects.preview.seek`, `effects.preview.play`, `effects.preview.stop` and `effects.preview.state` control the independent visual stage. Loading does not run or create a spell. The Effects workspace displays incoming MCP previews while protecting an unsaved local draft.

Parent cycles, sibling-name collisions and stale revisions are rejected. The same commands drive the UI and MCP.

The standalone player is ready for future world scenery consumers, but placing effects in the map editor is not part of this implementation.

## Eight mechanics examples

These are single-rank, Warcraft III-inspired mechanics examples with original artwork and our game's combat balance. They are published and can be bound to any unit through the editor; the existing Marshal's Q/W loadout is preserved.

1. **Storm Bolt**: a homing projectile, damage at impact, 5-second stun (3 seconds against heroes), immediate channel interruption. Released projectiles survive caster death; dead/untargetable or newly allied targets fizzle. The projectile follows live positions and resumes visually after load.
2. **Entangling Roots**: 9-second movement/attack restriction, 15 damage each second, including the final tick. Heroes receive a 3-second duration. Casting is allowed. Refresh replaces rather than stacks the status and restarts its periodic clock.
3. **Bloodlust**: +40% attack speed and +25% movement for 60 seconds through the shared resolved-stat path. Right-click the game command or use the workbench toggle for autocast. Autocast is saved, costs ordinary mana, obeys cooldowns/visibility, and avoids already-buffed recipients.
4. **Chain Lightning**: four distinct targets, nearest visible eligible target with entity ID tie-breaks, 15% damage reduction per hop. Each segment uses its previous impact as its visual origin.
5. **Shockwave**: a 24-unit swept line, 1.8-unit half-width, 75 damage once per victim, including enemy structures. Ground targeting previews direction; geometry tests each traversed segment so fast waves cannot tunnel through a target.
6. **Vampiric Aura**: nearby friendly melee units gain 15% lifesteal on actual ordinary attack damage. Multiple sources of the same aura do not stack; the highest rank then lowest source ID wins. Membership is rebuilt before navigation/combat, so moving out or losing the source removes the modifier. Ability damage cannot trigger lifesteal.
7. **Feral Spirit**: two controllable 60-second forest spirits, using the existing forest-spirit model by design. They spawn on valid free terrain using their actual dimensions, require no supply, replace their caster's previous group, and have ordinary combat and ownership. This is an adaptation of the wolf-summoning example, not a new wolf model.
8. **Dispel Magic**: removes eligible positive and negative spell statuses in an area and deals 200 spell damage to enemy summons. Non-dispellable stuns and aura membership remain. Item statuses are a separate content vocabulary and are not implicitly dispelled.

### Durable mechanics and presentation

Status records contain declaration ID, source, owner, rank, cast identity, start/expiry and periodic clocks. The resolved-stat path reads their declared modifiers alongside equipment. Control restrictions use the same movement/combat gates as existing controls. Delivery records store their fixed-precision positions, target, hit history and attenuation; all are included in snapshots/checksums. Restore validates references and clocks before changing the live world. `declarative-sim-73` separates this build from older peers/saves.

Live projectile positions are observer-filtered independently of caster visibility. The render layer reconstructs missiles and statuses after loading, follows authoritative positions, and removes status cues on dispel/expiry/death. It cannot apply gameplay damage. `beam`, `missile` and `wavefront` are reusable cue shapes; textures can use normal/additive blending and ground-facing or camera-facing orientation. New original effect textures are `asset.effects.storm-hammer`, `asset.effects.living-roots`, and `asset.effects.seismic-crescent`. Eight new icons use the `asset.icons.spell-<name>` convention. Full generation prompts live with asset provenance; runtime icons are 128px and effects 256px.

Bounds: 512 in-flight deliveries per world; 128 victims per line/area; 16 chain hits; 32 statuses per actor; eight summons per operation. These are engine capability limits, not visual settings. A summon may produce fewer units if no valid placement exists. New spells must stay within these limits; sound, corpse targeting and movement forms are separate capabilities.


### Layered ground auras

An effect composes up to 32 visual layers. A spell presentation links published effects through event bindings. Use `shape: "billboard"`, a published transparent `texture`, and `orientation: "ground"` for a ground-facing symbol. `follow: true` follows the recipient. `shape: "glow"` provides the soft untextured light pool. Put layers at slightly different `height` offsets to avoid coplanar flicker.

`lifetime: "status"` on a spell effect binding binds its target `statusApplied` effect to the actual observed status: steady opacity, no finite fade/restart, removed on expiry, dispel, range loss, or death. It supports billboard, glow, ring, and light layers. Regular finite cues retain their existing envelopes. Aura animation uses the world tick phase, so rebuilding membership each tick, load, visibility re-entry, and preview seeking do not restart the cycle. Timed statuses use their start tick.

Reusable `motion` channels are independent:

```json
{
  "rotation": {"periodTicks": 320, "direction": "clockwise", "phaseDegrees": 0},
  "scale": {"periodTicks": 80, "min": 0.72, "max": 1.06, "easing": "bounce", "phase": 0},
  "opacity": {"periodTicks": 80, "min": 0.7, "max": 1, "easing": "sine"}
}
```

There are 40 simulation ticks per second. Scale and opacity pulse between their bounds; `sine`, `smoothstep`, and `bounce` are supported. The Effects layer inspector's **Motion** controls expose these channels, direction and phase, alongside sustain, follow, orientation and blending. The spell owns status lifetime; an effect can also sustain or loop independently. MCP uses the same document schema through `spell_schema` and normal save/publish commands. No spell names are consulted by the renderer or these controls.

Vampiric Aura uses a constant violet glow, an eight-second outer wreath rotation, and a two-second bouncing inner bat crest. Thorns Aura uses an emerald glow, a twelve-second reverse-rotating bramble wreath, and a 2.8-second breathing thorn-heart. Four original generated ground textures are 512×512 RGBA; the Thorns command icon is 128×128. Generation descriptions live in each `art/assets/asset.effects.{vampiric-wreath,vampiric-crest,thorns-wreath,thorns-heart}/generation.json`.

Thorns grants `meleeReflectionPermille: 200` through the shared status/item modifier path. Ordinary hostile melee hits return 20% of actual post-mitigation, post-shield damage, capped by the defender's remaining health, as spell damage (with the attacker's normal spell mitigation). Ranged/projectile/shell attacks, ability damage, zero damage, and returned damage cannot trigger reflection. Returned hits use ordinary shields, rescue, death and experience handling. The same aura does not stack; leaving its range or losing its source removes the modifier.


### Retained-hero reincarnation

A holder `death` trigger may execute `revive` with a unique operation ID, ranked delay (`amount`), health/mana permille, placement radius and a bounded placement wait. It schedules return of the existing fallen hero, preserving identity, progression, equipment and learned abilities. It cannot be used on ordinary units, live actors, arbitrary recipients or a status-source executor. Trigger `cooldownTicks` is generic, rank-aware and saved; qualification checks it before spending mana or advancing proc counters.

Pending returns reserve supply and a unit slot and prevent duplicate altar revival. Losing supply capacity does not cancel an admitted return. The hard unit limit and actual spatial clearance still apply; blocked returns retry until the declared deadline, then leave the hero fallen and available for ordinary altar revival. Ownership changes cancel the pending return. Save validation checks provenance, rank, operation, timing and cooldowns before mutating state. Owner/visible-point filtering governs the waiting visual, which reconstructs at its original phase after load, seeking or sight re-entry.

### Permanent unit conversion

`convert` transfers a living non-hero recipient to the executing source's owner without spawning a replacement. It uses the ordinary recipient/query/filter pipeline and spell-immunity checks. `amount: 1` means one transfer per selected recipient; an optional query chooses a bounded group. Supply policy is `require` or explicit `allow-over-cap`; both obey the hard unit limit including queued reservations. Direct targets are checked before cost and again at release; group operations permit partial success in stable query order.

The transfer preserves identity, definition, exact position, health/mana (clamped to the new owner's resolved maxima), equipment, learned ranks, spell/weapon/charge cooldowns, timed statuses and summon expiry. Preparation/channeling is cancelled, old commands and employment/jobs are detached, carried goods remain with the unit, and old aura membership is removed. Existing source-owner checks end old spell deliveries and persistent instances on their next lifecycle step. The new owner's research applies; old-owner technology is not copied. Captured summons are excluded from their original summoner's replacement sweep. Taking a camp creature clears its camp allegiance without awarding a kill, experience or camp loot. Player destinations require the unit's authored `playerControl` capability; the neutral creature archetype now declares it, while ordinary ownership checks still prevent issuing commands to uncaptured creatures. Spell bindings retain their authored player/AI permissions.

### Containment and digestion

`contain` places each selected living non-hero unit inside the source unit. It has a unique operation ID, rank-scalable duration, `lifetime: duration | untilDeath`, capacity 1–8, and optional digestion (`intervalTicks`, ranked damage, registered damage type). It uses the ordinary recipient filters and spell immunity. Direct admission is checked before cost and again at release; queried recipients fill capacity in stable order. The strictest active capacity applies across different containment abilities. Self/nested containment and occupied carriers are rejected. A loaded carrier cannot enter a lookout.

The passenger keeps identity, owner, definition, health, equipment, cargo, spell ranks/cooldowns and supply cost. Orders/jobs and pending casts end, with the normal preparation refund. It has no model, collision, movement, attack, targeting, aura emission, vision or natural regeneration while held. Existing timed statuses and summon expiry continue. Source-bound persistent spells end when their source becomes unavailable; deliberately detached ground effects retain their authored lifetime. Digestion uses the ordinary damage/mitigation, shields, rescue, kill and XP path. A digested unit leaves no reusable corpse. Independent existing periodic statuses can still damage a held unit.

Expiry, carrier death/removal or conversion releases surviving passengers at the carrier through normal spatial clearance. If placement is blocked, the passenger waits off-map in the existing release queue until space opens. `releaseContained` explicitly releases a selected carrier's passengers; use a self spell for an unload command. Each successful entry emits `contained`, each digestion pulse `digested`, and each release `releasedContained`, with per-passenger anchors. ## Weapon-release programs

`triggers.event: weaponRelease` captures a learned passive or active `whileStatus` grant when a valid ordinary attack commits, after range/terrain validation and before attack-triggered concealment removal. Interrupted, disarmed, invalid and out-of-range windups do not count. Melee, arrow and siege weapons share this callback; optional `weapon` restricts the kind. Only hostile targets qualify, with optional target-trait `filter` and `includeBuildings` (off by default). Optional `blockedBySilence` suppresses the proc without suppressing the ordinary weapon. Filters run before every-N counting, chance, mana and cooldown. Weapon enhancements have first claim on available release mana, followed by triggers in stable ability/status/declaration order. No extra hit is implied: release hooks run even when the later weapon impact misses, is absorbed or evaded. Use `weaponHit` for successful-damage procs instead.

A qualified program enters the existing saved bounded reaction FIFO (128 programs per tick, 512 pending). It captures source identity/owner/rank/position, weapon kind, target ID/point and observing players. It cannot mutate HP in the middle of the weapon damage batch. Dispel after commitment does not cancel it; source conversion cancels queued release programs. Source death does not cancel independent point/query payloads, but dead casters cannot receive self buffs. Lost or newly allied victims cannot receive direct target effects; caster and captured-point payloads can still execute. Operations use the shared interpreter and cannot recursively generate ordinary hit procs; real resulting deaths still use bounded lifecycle reactions. The `weaponRelease` presentation binding and timeline marker describe qualified programs, not every unmodified attack. All policies are exposed by the same schema in the inspector, MCP and assistant.

**Battle Rhythm** (`/spells/neutral`) demonstrates every-third-release composition: 15/25/35% attack speed for four seconds, refreshing a dispellable status. A gold pulse marks activation and small rising embers follow the actual buff lifetime. This is a custom category proof inspired by RTS attack passives, not an exact Warcraft ability. It works with normal melee, arrow and siege combat without a spell-specific AI or editor branch. Select enemies, enable Combat and press Cast in the workbench. It reuses the Bloodlust command icon pending the final art pass. Flying movement and manual single-shot attack orders remain separate unfinished categories.

### Manual weapon abilities and autocast (2026-10-03)

`weaponCast: {bonus, weapon: melee | projectile | any, status?}` declares an enemy-targeted single enhanced normal attack. Bonus supports rank parameters; optional status references a target-only, independently timed template in `statuses`. Spell preparation/recovery must be zero: the unit's actual weapon supplies approach, facing, windup, recovery, projectile speed, damage type and hit handling. Channel, delivery, persistent, aura, passive combat modifiers and `onRelease` programs cannot also be declared. Triggers can compose through the normal combat/lifecycle paths. This supports melee and straight projectile weapons; siege shells are rejected.

A manual command validates learned binding/control, visibility, relation/filter, immunity, mana, cooldown and compatible weapon. Authored targeting range bounds command admission and pursuit; it does not extend weapon reach. Accepted commands issue an ordinary attack order and save a one-release `weaponOrder`, without reserving mana. The release rechecks eligibility, spends one cost and starts cooldown. Move/stop, source loss or conversion, profile/rank changes, invalid targets, silence and insufficient mana cancel before release. Cancelled shots cost nothing; committed misses are not refunded. After release the ordinary attack order continues. With autocast off, subsequent shots are ordinary attacks.

`autocast` uses the existing saved player command and binding AI permission, but decorates attacks already being made rather than choosing a new target or overriding movement. Ordinary utility autocasts cannot interrupt an explicit pending weapon cast. If no qualifying enhancement is affordable/off cooldown, the normal shot fires. Autocast and passive/status grants share the existing strongest-affordable selection; one grant and payment per attack. Equal bonuses use stable declaration order. A manual weapon cast explicitly selects its own enhancement. Impact marks, mitigation, evasion, shields, critical strikes, flight ownership/rank snapshots and detached projectiles use the existing weapon pipeline.

The workbench's passive-target mode selectively permits the manually commanded caster to approach and fire once, resolves its live projectile and impact, and keeps dummies stationary. ### Contextual amounts and sacrifice (SIM75)

`heal`, `damage`, `drain` and `mana` accept optional `scale` alongside their existing fixed/ranked `amount`. A scale reads `health`, `maxHealth`, `missingHealth`, `mana`, `maxMana` or `missingMana` from `caster`, the primary unit `target`, or the current `recipient`. The expression is `amount + floor(stat × permille / 1000)`, floored and bounded to 0–1,000,000. The ranked multiplier is bounded to 0–10,000. Point aims have no resource stats; areas use `recipient`. Caster and primary-target values are snapshots for this release/impact/wave; recipient values are refreshed before each operation. Detached work saves the source's health/mana capacities along with its ownership context. Restoring a save rejects missing required contexts/resources and invalid capacities before mutating the game.

Resource operations and `sacrifice` can declare a unique `record` name. A later magnitude may use `{source: "result", id: "offering", stat: "applied" | "count" | "health" | "maxHealth" | "mana" | "maxMana", permille}`. Records aggregate actual successful recipients: post-mitigation/clamped applied amount, successful count and their pre-operation resource values. An immune, skipped, zero-applied or unchosen branch contributes nothing. Records are local to one interpreter hit, never saved or shared between waves, chain links, casts or trigger programs. Forward references and duplicate names are rejected. A result from an unchosen branch reads zero. Queries aggregate across their recipients; a following query receives that aggregate, not an implicit per-recipient correspondence. Chain retention scales each resource operation's resolved amount; deriving another operation from an already-scaled result therefore applies that subsequent operation's retention too. No arbitrary expression language or scripting is introduced.

`{op: "sacrifice", target: "target", amount: 1, record: "offering"}` consumes an owned living non-hero unit other than the caster. Queries and filters use the ordinary recipient system. Contained, garrisoned and releasing occupants are ineligible. A live source must retain the original owner. Direct targets are admitted before cost and rechecked at release; all executions recheck ownership and life. Sacrifice bypasses damage mitigation, still obeys spell immunity, and invokes ordinary death cleanup, corpse creation and death programs. It emits `sacrificed` only on success. The reward is a separate resource operation reading the record, so a failed sacrifice cannot fabricate its output. AI predicts this resource sequence on copies of visible actors and counts the lost unit against restoration utility.
