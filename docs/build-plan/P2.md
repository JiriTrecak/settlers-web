# P2 — next systems

Not more buildings. Not water. Not sound. Those don't change the machine.

Four pillars: **controllable units**, **flatten**, **N players in one match**, **lockstep-shaped sim**. Everything below is in service of those. AI can be a script. Netcode is last.

Do them in this order. Later steps assume earlier ones exist.

## 4. Flatten

**Why.** You can plop a sawmill on a hillside. That’s a lie, and every new hut makes it more expensive. Same argument as FoW: put the nasty bit in so later defs just set a flag. Also makes fog *height* snapshots real.

**What exists.** `canPlace` checks landscape type + protected overlap + owned land. Heights are ignored. No digger profession. Construction does not wait on flat.

**Do this.** (Vertical slice on **one** hut — lumberjack — then the rest of the defs grow `flatten: true`.)

- A plot is flat when every `protected` tile shares the same height (or original’s slightly softer rule if we copy it — don’t invent a 3-height tolerance).
- Ghost goes red if not flat. Place still drops a **plan**.
- Plan does not become `building` until the plot is flat (in addition to construction goods).
- Digger: bearer `become`s digger, walks `buildMarks` / flatten marks, changes height ±1 per swing toward the target height (mode of the footprint, or the door tile — pick one, put it in the def comments). Dirt as a good can wait one slice if the height change alone is visible.
- Landscape mesh must pick up height changes (dirty verts, or rebuild the mesh for now). Grey FoW tiles must sample `hiddenAt` height once flatten exists, or the ghost landscape jumps.
- Test: lumberjack on a 2-level slope. Plan sits. Digger levels. Then bricklayers. A flat grass plot still constructs as today.

**Not this step.** Full dirt economy, raise-only mountains, mines.

**Bar.** You cannot finish a lumberjack on a slope without flattening. Mesh matches.

## 5. Second player, dumb script

**Why.** FoW vs an enemy, rims bumping, occupy-not-steal, per-player matcher. AI is not a brain — it is “the other slot emits the same `Action`s.”

**What exists.** `player` on units/huts/land/fog. Clothing color from lobby. One colony at `starts[0]`. Fog `view(player)` is already per-player.

**Do this.**

- Match config: `players: number` (2 is enough). Place a colony at `starts[i]` for each slot (dumped maps already have starts).
- Local view is `world.view(myPlayer)` — you already do this. Confirm enemy units hide at sight ≤50, enemy huts snapshot in grey, you cannot place on their land.
- Overlapping occupy: existing rule (don’t steal `towerCount > 0` except ground cell). Put two towers close; rim sits on the contact line. Test it.
- **Script AI:** after kit, enqueue a few actions on a delay — e.g. place a tower toward the opponent, spawn/send a pioneer. Same queue as the human. No pathfinding AI module.
- Defeat stub optional: if a player’s last occupying building is gone and they have no pioneer, they lose. Can wait until combat.

**Not this step.** Construction-finder, difficulty, 8-player, fog-of-war cheating AI.

**Bar.** Load a 2-start map, see two blobs, grey between them, two rims, goods don’t cross.

## 6. Combat / soldiers

**Why.** Army without HP/attack/death is pioneers in helmets. Towers occupy; they don’t shoot.

**What exists.** No health. No attack job. No garrison. Delete-hut is a debug verb.

**Do this.**

- Soldier def(s): `needsPlayersGround: false`, `viewDistance` as original. Select + `moveTo` reuse step 3.
- `health` on the movable. Melee: stand adjacent, `attack` job, tick damage, die → remove unit, unstamp fog circle (same as destroy hut).
- RMB on enemy unit/hut = attack. RMB on ground = walk.
- Tower garrison can wait one slice; first bar is two soldiers fighting on the contact line so FoW + land + death are visible.
- Destroying a military hut in combat uses the same `destroyBuilding` path (unstamp land + fog).

**Not this step.** Balista, swordsman vs bowman tables, priests, thief.

**Bar.** You can send a soldier into the fog, fight, watch the body vanish and grey close in.

---

## 7. Netcode (last)

**Why.** If 1–6 are on the action pipe, this is transport + delay, not a rewrite.

**Do this.**

- Lockstep: tick N waits until every player’s actions for N arrived (empty list is an action).
- Command delay: enqueue at `tickIndex + D` (D ≈ 2–8 ticks). Same D in single-player once this exists, so the feel matches.
- Payload: `{ tick, player, action }[]` + checksum every N ticks. Desync = halt + dump logs.
- Replay file = seed + map id + log. Same as the step-1 test, over the wire.

**Not this step.** Dedicated server sim, rollback, NAT punch as a product.

**Bar.** Two browsers, one map, same checksums. That’s the game.
