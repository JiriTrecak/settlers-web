# Main menu

The illustrated first screen uses four independent published assets under `asset.interface.main-menu`: `forest-aftermath`, `panel-charcoal`, `logo-oak`, and `button-charcoal`. The scene is a dark, insect-scale ruined settlement. Its background contains no UI, fire, smoke or light shafts. Live HTML buttons preserve Campaign, Skirmish, Multiplayer, Map Editor, Settings and Exit, including keyboard focus. Labels are small white serif text over near-black timber. Settings keeps player name, graphics and fullscreen controls.

`menuEffects.ts` adds masked cool canopy rays, three local fires, smoke and embers using Canvas 2D. Emitter and hand-traced occlusion coordinates use the background's 1672 × 941 dimensions. The canvas applies the same centered cover transform as the illustration, including on narrow windows. Soft ray textures are cached, then swept and pulsed in a half-resolution buffer behind a stationary occlusion mask; illuminated dust drifts through the shafts; smoke sprites are cached; the overlay is capped at 1600 pixels wide and 30 fps. It pauses in hidden tabs, renders a still frame for reduced motion, and releases its animation, observer and event listeners when the menu closes. These are menu-only presentation effects, not map or biome settings. To change the scene composition, update the emitters and occlusion paths together.

Artwork was generated with built-in ImageGen from the approved menu concept. Exact production brief summaries and encoding metadata live in each package's `generation.json`. Regenerate separate clean plate/panel/logo/button PNGs, then publish through `scripts/assets/publish-menu-aftermath.ts <input-directory>`; it trims transparent UI bounds, optimizes WebP, and publishes via AuthoringStore. Final runtime assets total about 0.91 MB. Original generated images are not duplicated in the repository.

The small bottom-right version/changelog plaque uses the installed version from the shared release system, with no scroll icon. Desktop builds continue checking for updates when the menu opens; downloads and installation remain explicit. Release history and its keyboard-accessible image gallery are unchanged. See `infrastructure/releases/README.md` for the release workflow.

## Campaign selection

Campaign opens with a short fade to three carved faction panels over the same forest and live effects. The campaign-only overlay dims the scene by 70%; the main menu stays unchanged. Independent transparent ant, beetle and bee crests are published under `asset.interface.campaign`. Queensguard (ants) opens the existing mission list; beetles and bees are disabled preview states with “Finish ant campaign first” copy. These draft locks do not yet read campaign completion. The saved campaign identifier remains `vanguard` to preserve existing missions and progress. Back and Escape return through the selector to the main menu. `MenuTransition` guards repeated activation and cancels on disposal; reduced motion skips fades.

Regenerate crests with the built-in ImageGen prompts recorded in `scripts/assets/publish-campaign-crests.ts`, then publish three named PNGs through that script. Only the optimized transparent WebP assets and generation metadata are stored in the canonical asset packages.
