# Authored maps

A `.utcmap` v3 document declares its map size and stores committed editable terrain in `authoring.terrain`, ordinary authored objects, scenery stamps, decals, player starts, gameplay placements and neutral camps. Terrain contains heights, local water surfaces and flow, ground-material coverage and saved tile variations. Saved maps contain no generator layers, curves, seeds or derived render/navigation artifacts. Loading does not execute generators. Earlier procedural formats are rejected rather than migrated. The typed map contract requires terrain, and rendering, simulation, AI and placement validation all use its committed samples. A missing terrain document or mismatched dimensions is an error; loading never substitutes flat ground or an old global water level.

Generators are editor tools. A preview is separate from the saved map; **Apply previews** commits the result as editable terrain and placements in one undo step. Later cell edits or object deletion do not regenerate it. Grid levels, cliffs, banks, directional ramps, material painting and water selections all edit the same terrain. Optional sculpting edits that terrain too. See [the editor guide](../../../docs/editor.md).

Placements reference persistent definition IDs and explicit owners. Starting setup references expand to stable authored keys; each player binds one main-fort objective. `playable.ts` validates references, starts and occupancy before a map can be launched. Revision combines canonical map and content fingerprints. `library.ts` discovers valid project `.utcmap` files in campaign, skirmish and showcase folders and current-format locally saved maps. Editor and Singleplayer use the same library. Project map menus use the generated overview/thumbnail index; terrain files are separate dynamic imports. `getMap` returns metadata only, while `loadMap` explicitly loads and validates the selected document and shares concurrent requests. Revisions are computed only when match/save validation needs them. Cancelling or changing a selection cannot open an older pending map. Local map hydration still reads ordinary saved documents from IndexedDB.

`MAP_SIZE` is only a default. Runtime indexing uses the loaded map's size. Loading a different size rebuilds height, brush, terrain, water, fog and camera bounds. Terrain arrays include the declared render halo and are rejected when dimensions disagree. Map coordinates are `[0, size)`, cell indices use `y * size + x`, and fixed-point motion uses the same map-specific stride. Snapshots validate dimensions against the loaded map. Different-sized simulations can coexist without changing global dimensions.

Ground units wade through depths up to `WADING_DEPTH_CM` (60 cm). AI briefing and runtime navigation use the same threshold. Deeper water blocks movement; construction requires dry ground. **Grid · shallow water** authors a 32 cm bed and can raise a ford through deeper water. Banks are ground slopes under a horizontal water surface. Water appearance follows actual depth rather than a separate passability texture.

Warcraft import converts source terrain, water, texture choices and object positions into this same editable map format. Source neutral groups become local camps matched by difficulty; mine sites use amber nodes. The archive and source generators are not retained in the saved map. See [the importer](../../editor/import/warcraft/README.md) for supported inputs and current conversion limits.
